# Story 07.1 — AO-basis GF2 initial Matsubara Green's-function guess

## Status, dependencies, and scope boundary

This is the first numerical GF2 story. It constructs the **initial, noninteracting
Matsubara Green's function** in the regular, nonorthogonal AO basis, including
the static restricted Hartree–Fock self-energy formed from the supplied AO
density matrix and density-fitted interaction tensor.

It is deliberately **not** a self-consistent GF2 implementation. In particular,
there is no dynamic GF2 self-energy, no imaginary-time diagram evaluation, no
Fourier transformation, and no update of either the density matrix or chemical
potential.

This is a feature story, not an infrastructure story. It applies the parser,
loader, Tensor, Matsubara-grid, and dense-solve facilities that already exist or
are specified by its dependencies. It must not introduce a new loader framework,
a private linear solver, a new Tensor contraction system, a factorization cache,
or a separate external-fixture generation pipeline.

### Dependencies

- **Story 05 — Input parsing & data loading (GF2).** Reuse its `ParsedInput`,
  central parameter registry, `Gf2Input`, `load_gf2(...)`, HDF5 validation, AO
  dimension conventions, and declared symmetry metadata. This story makes only
  the narrow additions needed to load `overlap` and `density_matrix`; it must
  not introduce another parser, another HDF5-opening path, or a general Loader
  abstraction. A proper structured HDF5 Loader is deferred to
  [Story 08](08-loader.md).
- **Story 06 — Tensor index symmetry & backend seam.** Input `hcore`,
  `overlap`, and `density_matrix` are Hermitian AO matrices; `eri3` is symmetric
  in its AO pair. These remain advisory input metadata, exactly as in Story 05.
  This story does not infer or propagate output symmetry.
- **Story 06.1 — General Tensor axis permutation.** Its physical permutation
  primitive is already available if a later layout conversion requires it. The
  HDF5 layout used here is the already-supported Story-05 layout, so this story
  must not add a redundant transpose/permutation on load.
- **Story 06.2 — Dense host matrix solve through the Tensor backend.** This
  story consumes its tested public Tensor `solve(A, B, X, axes)` feature for
  `std::complex<double>` coefficient/RHS work tensors. It must not add a
  private GF2 solve, an explicit inverse, direct backend calls, or a second
  LAPACK binding.
- Existing `MatsubaraGrid<Fermionic>` and
  `GridExpansionMatsubara<std::complex<double>, Fermionic>` facilities.

### Goal

Given a real AO core Hamiltonian `H_0`, overlap `S`, density matrix `P`, and
three-index density-fitting tensor `B`, construct

```text
Σ_HF[P]                       (static AO self-energy)
F = H_0 + Σ_HF[P]             (static AO Fock-like matrix)
G_0(iω_n) = [(iω_n + μ)S - F]⁻¹
```

for every point on a finite fermionic Matsubara grid. The inverse notation is
mathematical only: the implementation must solve a linear system against the
ordinary matrix identity and must not explicitly form an inverse.

The output is a complex, matrix-valued Matsubara expansion suitable as the
first input to a later GF2 self-consistency story.

## Physics and conventions

### Restricted closed-shell convention

This story uses the restricted, closed-shell convention with a **spin-summed**
AO density matrix `P`. Its normalization is

```text
N_e = Tr(P S),
```

where `N_e` is the total number of electrons. This is a validation and logging
quantity; it is **not** the chemical potential.

The static self-energy uses the corresponding Coulomb-minus-half-exchange
form:

```text
ρ_Q = Σ_kl B^Q_kl P_kl

J_uv = Σ_Q B^Q_uv ρ_Q

K_uv = Σ_Qkl B^Q_ul P_kl B^Q_kv

Σ_HF,uv = J_uv - 1/2 K_uv.
```

All repeated AO indices range over the same AO basis, and `Q` ranges over the
RI/density-fitting auxiliary basis. The formula assumes that the input `eri3`
uses exactly this convention and the same AO ordering as `hcore`, `overlap`,
and `density_matrix`.

This story supports only real `double` input tensors and produces
`std::complex<double>` Green's functions. Spin-unrestricted, complex-valued
input integrals, alternative density normalizations, and alternative RI
factorization/sign conventions are out of scope.

### Chemical potential

`μ` is an independent scalar input. It must **not** be computed as `Tr(P S)`.

For this initial-guess story, `μ` is accepted as supplied. A later
self-consistent story will determine or adjust it so that the Green's function
has the desired particle number. That later procedure will need a precise
particle-number evaluation from `G`, a target electron count, bracketing or
root finding, and a finite-grid/tail treatment; none belongs here.

### AO Dyson equation and solve convention

For a fermionic Matsubara frequency `ω_n`, define the complex AO matrix

```text
A_n = (iω_n + μ) S - H_0 - Σ_HF
    = (iω_n + μ) S - F.
```

The Green's-function matrix is defined by the right solve

```text
A_n G_0(iω_n) = I,
```

where `I` is the ordinary dense matrix identity used as the right-hand side of
the linear system. In particular, **do not** replace this RHS with `S`.

For every frequency, the implementation constructs `A_n`, creates an identity
right-hand side, and solves for all columns of `G_0(iω_n)` together through the
completed Story-06.2 host solve primitive. If that primitive reports a singular
matrix, this layer must add the Matsubara frequency/index to the error rather
than returning partially initialized data.

### AO high-frequency convention (documented, not implemented here)

The nonorthogonal AO basis changes the matrix-valued high-frequency moments.
For this story's convention,

```text
G_0(iω) = S⁻¹/(iω)
        + S⁻¹(F - μS)S⁻¹/(iω)²
        + O(ω⁻³).
```

Thus its leading tail coefficient is `S⁻¹`, **not** the ordinary identity.
This is important to the tail-subtraction and inverse-Fourier machinery from
Stories 03–04, but no Fourier transform is performed in this story. A later
AO-basis Fourier/tail story must use these basis-dependent moments rather than
assuming `I/(iω)`.

### Green's-function symmetry is deferred

The loaded real static matrices may carry Hermitian/symmetric *input* metadata
as specified by Story 05. Do not attach a Hermitian `SymGroup` to each
frequency slice of `G_0` in this story.

A Green's function is Hermitian in the appropriate imaginary-time sense, but
at fixed Matsubara frequency its relevant relation for a Hermitian static
problem is

```text
G(-iω_n) = G(iω_n)†
```

where `†` denotes the conjugate transpose. For the real AO convention used
here this reduces to complex conjugation (the coefficient matrices are real
symmetric, so each fixed-frequency Green's-function matrix is symmetric as
well). This couples the positive and negative frequency slices; it is not a
same-slice Hermitian transpose symmetry expressible by the current pairwise
`SymGroup` metadata. A later Fourier/symmetry story must specify how tau-space
Hermiticity and the `+ω`/`-ω` Matsubara relation are represented, checked, and
preserved by transforms. This story computes every
grid point independently and does not enforce, declare, or test that relation
beyond ordinary numerical correctness of the solve.

## Minimal integration with Story 05 loading

Story 05 already establishes the only input parser and HDF5 access route used
by GF2. Keep that architecture:

```text
parse_input_file(...) → ParsedInput → load_gf2(...) → Gf2Input
```

This story extends that existing route rather than adding a parallel
`ifstream`/HighFive parser or a general data-access layer.

### New registry entries and GF2 requirements

Add the following rows to Story 05's central parameter registry and resolve
them through its existing requirement/default machinery:

| keyword | kind | required for GF2 initial guess | meaning |
|---|---|---:|---|
| `OVERLAP` | String | yes | HDF5 path to the AO × AO overlap matrix `S` |
| `DENSITY_MATRIX` | String | yes | HDF5 path to the AO × AO spin-summed density matrix `P` |
| `BETA` | Double | yes | positive inverse temperature `β` |
| `MATSUBARA_HALF_N` | Int | yes | positive number of positive fermionic frequencies / half-grid size |
| `MU` | Double | yes | initial chemical potential |

`ParamKind` therefore gains the already-anticipated `Int` case. Integer
parsing must require full-token consumption, reject signs/fractions/exponents,
and reject zero or negative `MATSUBARA_HALF_N` during GF2 input validation.
`BETA` must be finite and strictly positive. `MU` must be finite. These
physical range checks belong in the GF2 input-loading boundary, not in the
generic lexical parser.

The existing Story-05 keys remain unchanged:

- `HCORE` and `ERI3` remain required and are used here.
- `MO_COEFF` remains required by the current Story-05 GF2 schema and remains
  loaded by `load_gf2(...)`, but this AO initial guess does **not** use it.
  Do not add an AO→MO transformation merely because those coefficients are
  present. The future Loader story can rationalize calculation-stage-specific
  data requirements without changing this bounded numerical story.
- `ETA` remains parsed/defaulted exactly as Story 05 specifies, but is unused:
  real-frequency broadening has no role in this Matsubara solve. Do not thread
  it into `A_n`.

### Narrow extension of `Gf2Input` and `load_gf2`

Extend the existing `Gf2Input` returned by `load_gf2(...)`; do not create a
second independent input struct that rereads `hcore`/`eri3`.

```cpp
struct Gf2Input {
  // Existing Story-05 fields, retained unchanged.
  Tensor<double, Executor::Host> hcore;
  Tensor<double, Executor::Host> mo_coeff;
  Tensor<double, Executor::Host> eri3;
  double eta = 1e-5;

  // Added by this story.
  Tensor<double, Executor::Host> overlap;
  Tensor<double, Executor::Host> density_matrix;
  double beta;
  size_t matsubara_half_n;
  double mu;
};
```

`load_gf2(...)` continues to be responsible for opening the HDF5 file once and
for using the existing Story-05 dataset/type/rank validation path. Extend that
same path to read `OVERLAP` and `DENSITY_MATRIX`; do not copy-paste a new
per-dataset HighFive validation routine in the GF2 numerical code.

Validation before returning `Gf2Input`:

- `hcore`, `overlap`, and `density_matrix` are rank-2 `float64` datasets;
- each is square, and all have the same `N_AO`;
- `eri3` is rank-3 `float64`, with both AO extents equal to that `N_AO`;
- `mo_coeff` and `eri3` retain every existing Story-05 check;
- all values of `beta`, `mu`, and `matsubara_half_n` meet the ranges above.

Declare `overlap` and `density_matrix` with fresh, separate `Hermitian()`
handles on their two AO axes, in the same advisory-metadata style used for
`hcore`. This is a declaration of the expected physical input, not a numerical
check that the datasets are exactly symmetric/Hermitian. `eri3` retains its
existing `Symmetric()` AO-pair metadata.

The absence of data-validity checks is intentional and consistent with Story
05/06. A later input-validation story may check `S=S^T`, `P=P^T`, positive
definiteness of `S`, etc.; this story only needs errors that prevent a defined
calculation (missing datasets, wrong type/rank, inconsistent dimensions, or
failed linear solve).

### Explicitly deferred Loader work

Do not turn this extension into a generic `Loader` class, a schema registry,
or a lazy HDF5 object graph. The small duplication still present in Story 05's
concrete `load_gf2` implementation is deliberately contained there for now.
The desired generalized design and its non-goals are captured in
[Story 08](08-loader.md).

## Data representation and layout

### Existing loaded tensors

Use Story 05's established HDF5-to-`Tensor` mapping unchanged. In particular,
HDF5 data are read directly in their native contiguous order; no active
transpose is needed or permitted merely to rename axes.

The physical components used by the formulas above are:

```text
hcore(u, v)          = H_0,uv
overlap(u, v)        = S_uv
density_matrix(k, l) = P_kl
eri3(u, v, Q)        = B^Q_uv
```

where the final coordinate notation follows `Tensor`'s fastest-to-slowest axis
order. For `eri3`, Story 05's physical HDF5 `(ri, ao, ao)` ordering is retained
in contiguous storage while the Tensor dimensions are the established
fast-to-slow `{ao, ao, ri}` order. The numerical implementation must use
positions, not `label_index("ao")`, because the two AO labels form one
symmetric family and are intentionally duplicated.

### Derived static matrices

`rho`, `J`, `K`, `sigma_hf`, and `F` are temporary/returned real quantities in
this story. Their public representation should be explicit rather than
implicitly overloading duplicate `ao` labels:

```text
rho(Q)                     RI vector
sigma_hf(u, v), F(u, v)    dense AO matrices
```

The implementation may retain these as private contiguous working buffers for
this first numerical primitive. If exposed in a result type, use clear
position-specific matrix labels such as `ao_row` and `ao_col` rather than
claiming a new `SymGroup` derived from arithmetic. Do not add symmetry
propagation rules to `Tensor`.

### Green's-function result

Add a small result type in `include/gf2.hpp`:

```cpp
struct Gf2InitialGuess {
  Tensor<double, Executor::Host> sigma_hf;
  Tensor<double, Executor::Host> fock;
  GridExpansionMatsubara<std::complex<double>, Fermionic> green;
  double electron_count;
};

Gf2InitialGuess make_gf2_initial_guess(const Gf2Input& input);
```

The exact public shape spelling may follow the existing expansion constructors.
The resulting `green.data()` must use the existing
`GridExpansionMatsubara` layout, i.e. the Matsubara representation axis is the
fastest Tensor axis:

```text
green.data()(n, u, v) = G_0,uv(iω_n)
shape: [matsubara, ao_row, ao_col]
```

Use distinct AO row/column labels for this derived complex matrix quantity
unless and until a later story defines frequency-pair symmetry metadata.

The `sigma_hf` field is the static Coulomb-minus-half-exchange self-energy.
`fock` is the separately exposed `H_0 + sigma_hf` matrix used by the Dyson
solve. Exposing both gives the integration fixture a direct static-HF reference
without conflating either quantity with a dynamic self-energy.

## Numerical work

### 1. Electron-count diagnostic

Compute

```text
N_e = Σ_uv P_uv S_vu.
```

For real symmetric inputs this is numerically the same scalar as the ordinary
matrix trace `Tr(P S)`. Compute it from positions so that the convention is
unambiguous. Return it in `Gf2InitialGuess` and include it in the CLI summary.
Do not round it to an integer, reject nonintegral values, or use it to alter
`mu`; fractional values can be legitimate in later finite-temperature and
intermediate iterations.

### 2. Static self-energy

Compute the quantities in a readable contraction order that does not materialize
a four-index ERI:

```text
rho(Q) = Σ_kl B(Q,k,l) P(k,l)

J(u,v) = Σ_Q B(Q,u,v) rho(Q)

K(u,v) = Σ_Qkl B(Q,u,l) P(k,l) B(Q,k,v)

sigma_hf(u,v) = J(u,v) - 0.5 K(u,v).
```

A direct host implementation with explicit loops is acceptable for this story.
It should prioritize correct index mapping and clear tests over introducing a
new general tensor-contraction API. Reuse existing raw tensor storage/access;
do not add an automatic contraction planner or an ERI expansion.

The implementation may later optimize the exchange expression via a sequence
of matrix products, but only if the resulting layout/index convention is tested
against the direct formula. Such optimization is not required for done.

### 3. Fermionic Matsubara grid

Construct exactly the existing grid type:

```cpp
MatsubaraGrid<Fermionic> grid(input.matsubara_half_n,
                              InverseTemperature{input.beta});
```

Do not hard-code a frequency-index formula in the GF2 code. Obtain each
frequency from `grid(n)` / `grid.points()`, preserving the existing ascending
negative-to-positive ordering. With half-size `N`, the fermionic grid contains
`2N` nonzero points.

### 4. Dense complex solves using Tensor `solve`

Use Story 06.2's public Tensor operation:

```cpp
solve(Awork, Iwork, Xwork,
      { SolveAxis{TensorDimLabel("ao_equation"),
                  TensorDimLabel("ao_row")} });
```

Do **not** call `TensorBackend::solve_in_place` directly from GF2 code, do not
bind LAPACK here, and do not form an explicit inverse.

For each grid point `n`:

1. Assemble a contiguous complex coefficient Tensor

   ```text
   Awork[ao_equation, ao_row]
     = (i*omega_n + mu) * S - H_0 - sigma_hf
   ```

   where `ao_equation` is the row/equation axis of the linear system and
   `ao_row` is the solved/domain axis that becomes the first AO axis of `G`.
2. Assemble a contiguous complex identity RHS Tensor

   ```text
   Iwork[ao_equation, ao_col] = δ(equation, col)
   ```

   using a distinct RHS/output-column label `ao_col` so the solve output has
   unambiguous labels.
3. Call the Tensor solve with the one explicit row/column axis pair above. The
   result has shape

   ```text
   Xwork[ao_row, ao_col]
   ```

   and satisfies `Awork * Xwork = Iwork`.
4. Scatter `Xwork(u,v)` into the strided Matsubara expansion storage as
   `green.data()(n,u,v)`.

Because the Matsubara axis is fastest in the expansion storage, an individual
matrix slice is strided. Use a contiguous per-frequency Tensor work matrix/RHS
and scatter the completed solution back to the expansion. Do not reinterpret a
strided frequency slice as a contiguous LAPACK matrix.

Each frequency has a different complex coefficient matrix, so this story
performs one solve/factorization per grid point and adds no factorization cache,
batched solve API, matrix inverse, or GF2-private LAPACK wrapper.

## Tests

Tests use the existing in-process `-t` suite plus a small CLI acceptance case.
They must extend existing Story-05 test fixtures/helpers rather than creating a
second unrelated HDF5 test framework.

### A. Parser and loading extension

Add focused coverage for the new keys:

- `OVERLAP` and `DENSITY_MATRIX` paths preserve case and are required for this
  GF2 initial-guess stage.
- `BETA`, `MU`, and `MATSUBARA_HALF_N` parse with the central registry's typed
  accessors.
- malformed integers (`4.0`, `1e3`, `x`, trailing text), zero/negative half
  sizes, nonfinite `BETA`/`MU`, and nonpositive `BETA` fail clearly.
- a self-contained HDF5 file containing all existing Story-05 datasets plus
  `overlap` and `density_matrix` loads successfully.
- wrong rank/type, non-square matrix, missing new dataset, and AO extent
  mismatch fail with the tensor/path/axis named in the error.
- loaded `overlap` and `density_matrix` have fresh shared `Hermitian()` handles
  on their AO pairs, just as `hcore` does; no data symmetry check is expected.

### B. Static self-energy reference

Use a small hand-written real fixture (`N_AO = 2`, `N_RI = 2`) with
nontrivial, non-diagonal `P` and `B`. Independently calculate `rho`, `J`, `K`,
and `sigma_hf` by direct reference loops in the test, and compare every result
to `make_gf2_initial_guess`'s `sigma_hf` within a tight floating-point
tolerance.

This test must specifically catch:

- swapping the two AO positions of `eri3` in only one exchange factor;
- omitting the `1/2` exchange coefficient;
- treating `rho_Q` as a scalar shared across `Q`;
- an incorrect `P(k,l)` index order.

### C. Electron-count diagnostic

For a non-identity overlap and a non-diagonal density matrix, verify

```text
result.electron_count == Σ_uv P_uv S_vu.
```

Also verify it is reported as a diagnostic only: changing supplied `mu` changes
`green` but does not change the returned electron count or trigger an implicit
chemical-potential update.

### D. One-AO analytic Green's-function solve

For `N_AO = 1`, choose nontrivial real `S`, `H_0`, `P`, and `B`. Compute the
scalar `sigma_hf` from the stated formula, then verify every grid point against

```text
G_0(iω_n) = 1 / ((iω_n + μ) S - H_0 - sigma_hf).
```

Use actual values yielded by `MatsubaraGrid<Fermionic>`, including both the
negative and positive frequency halves. This simultaneously validates grid use,
complex assembly, and storage/scatter order.

### E. Multi-AO solve residual

For a small well-conditioned `N_AO = 2` fixture, for every Matsubara point
reconstruct `A_n` and verify

```text
max_uv |(A_n G_n - I)_uv| < tolerance.
```

Use a residual tolerance appropriate for double-precision pivoted solves, e.g.
a small multiple of machine epsilon times a scale based on `||A_n||` and
`||G_n||`; do not compare to an explicitly formed inverse.

### F. End-to-end loader/solver fixture using existing test machinery

In addition to the small algebraic unit tests above, add one compact
end-to-end test fixture that uses the existing Story-05 input/HDF5 test
helpers and the ordinary production route:

```text
parse_input_file → load_gf2 → make_gf2_initial_guess
```

The fixture should be deterministic and small (`N_AO = 1` or `2`, small
`N_RI`, and a short Matsubara grid). It may write temporary HDF5/input files
from the C++ test harness using the same helper style already used by Story 05,
or reuse an existing checked-in/smoke fixture if one exists. Do not add a new
Python/PySCF generator, a CMake fixture-generation target, or a second HDF5 test
framework in this story. Independent PySCF comparison is valuable, but it is a
larger integration-fixture story and is deferred.

The end-to-end test should compare:

- every `sigma_hf` element against values computed independently by explicit
  reference loops in the test;
- every `fock` element against `hcore + sigma_hf`;
- every Green's-function value, including both negative and positive Matsubara
  frequencies, either against the one-AO analytic formula or against a residual
  check `A_n G_n = I` for the multi-AO case;
- the electron-count diagnostic against `Σ_uv P_uv S_vu`.

This test must exercise the normal loader and Tensor solve route. It must not
call a GF2-private solver, construct an explicit inverse, or duplicate the HDF5
loading path.

### G. Result representation and non-goals

Verify that:

- `green` has complex scalar type, a fermionic Matsubara grid, and exactly
  `2 * matsubara_half_n` points;
- the representation axis is the existing fastest Matsubara axis;
- its two AO axes use distinct row/column labels and have no incorrectly
  declared same-slice Hermitian `SymGroup`;
- the test does **not** assert `G(iω_n)^T == G(iω_n)`;
- `eta` has no effect on the constructed Green's function.

The final two checks prevent accidental import of real-frequency broadening or
tau-space symmetry assumptions into this Matsubara-only story.

### H. Failure behavior

Cover:

- singular/invalid solve fixture produces an exception that identifies the
  Matsubara point;
- mismatched AO dimensions fail during loading before numerical work;
- no Fourier transform, tail subtraction, density update, or chemical-potential
  root search is called by this test path.

### I. CLI smoke test

Extend the existing real HDF5 smoke fixture/input with the required new
keywords/datasets and verify:

```text
./cppgw -i gf2.in -d rhf_df.h5
```

constructs the initial guess, prints the bounded summary, and exits zero. A
missing `OVERLAP`, `DENSITY_MATRIX`, `BETA`, `MATSUBARA_HALF_N`, or `MU` must
produce an actionable nonzero failure.

  parser, HDF5 loader path, or general Loader class is introduced.
- `OVERLAP`, `DENSITY_MATRIX`, `BETA`, `MATSUBARA_HALF_N`, and `MU` are loaded

  `eri3` with correct AO/RI index mapping.

  grid by solving `A_n G_n = I` at every frequency, without explicit inversion.
- The Story-06.2 Tensor solve is used directly by the GF2 feature code and has
  deterministic residual, one-orbital analytic, and normal loader/solver route
  coverage for static HF/Fock matrices and Matsubara Green's-function points.

  used to transform or broaden this AO Matsubara initial guess.
- No dynamic GF2 self-energy, self-consistency, chemical-potential search,
  Fourier/tail operation, or Matsubara-frequency symmetry enforcement is
  implemented.
- The full existing test suite remains green.
